# Політика розробки та безпеки проєкту

## 1. Правила роботи з Git (Git Workflow)
* Усі нові функції розробляються в окремих гілках `feature/<назва>`.
* Прямий push у гілку `main`/`master` заборонений. Зміни вносяться тільки через Pull Requests.
* Повідомлення комітів повинні мати префікси: `[INIT]`, `[DOCS]`, `[FEAT]`, `[FIX]`.

## 2. Стандарти коду та безпеки
* Заборонено зберігати секрети, ключі шифрування та паролі у відкритому вигляді в репозиторії.
* Усі змінні середовища повинні зберігатися у файлі `.env`, який додається до `.gitignore`.
* Обов'язкове покриття юніт-тестами бізнес-логіки не менше ніж на 80%.

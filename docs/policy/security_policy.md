# Політика безпеки проєкту (Security Policy)

## 1. Мета та область дії
Цей документ визначає обов'язкові правила та принципи безпеки для розробки, експлуатації та супроводу системи автентифікації. Політика поширюється на вихідний код, сервери, середовище розробки та роботу з секретними даними.

## 2. Ролі та відповідальність
* **Lead Developer:** відповідальний за дотримання правил безпечної розробки та перевірку Pull Requests.
* **DevOps / SysAdmin:** відповідальний за безпечне середовище розробки, збереження секретів та налаштування мережевих екранів.

## 3. Принципи безпеки
* **Принцип найменших привілеїв (Least Privilege):** користувачі та компоненти системи мають лише ті права, які необхідні для виконання їхніх функцій.
* **Захист у глибину (Defense in Depth):** застосування багаторівневих систем захисту (2FA, хешування, валідація, HTTPS).
* **Заборона зберігання секретів у коді:** усі ключі API, паролі та сертифікати повинні зберігатися в змінних середовища (.env) або спеціалізованих сховищах.

## 4. Безпека розробки та перевірка коду
* Усі залежності проєкту повинні перевірятися на наявність відомих вразливостей.
* Перед злиттям коду в основну гілку обов'язкове проведення Static Application Security Testing (SAST).
